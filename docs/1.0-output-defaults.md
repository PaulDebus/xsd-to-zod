# 1.0 Output Defaults

Status: **decided** (2026-09). This document records the design decisions for the
1.0 output shape — what the generated code looks like, what the runtime does, and
what is deliberately out of scope. Related issues: #176, #182, #161, #211, #214,
#216, #231, #233.

## 1. Scalar collapse — already shipped

Non-repeated elements (`maxOccurs="1"` or absent) map to **scalar fields**, not
single-element arrays. This has been the default and only behavior since 0.2.0
(#148); GH#176's core premise was written against older output. No flag, no
metadata — nothing to do here.

## 2. Clean break at 1.0 — no compat flag

1.0 is a deliberate breaking release with **no `--compat` mode**. Support contract:
*regenerate with the version you run.* Old generated files are unsupported across
runtime versions; users who cannot migrate pin `@0.x` (a devDependency pin
reproduces the old output exactly). Rationale: a compat flag only preserves shapes,
not names, so consumer code breaks regardless; the runtime would carry dual parse/
serialize paths permanently; and 0.x has no stability promise to honor.

## 3. Ergonomic additions — temporary flag, then default

The two remaining GH#176 features land behind a **temporary `--ergonomic`
scaffolding flag**, deleted at the flip (never a config key, never public API):

- **Value-wrapper collapse:** element types with no element content and a single
  attribute (`{ "@value": T }`) collapse to scalar fields; the collapsed form is
  recorded per-field in xmlRegistry metadata so `serializeXml` can re-wrap.
- **Repeated-choice union arrays:** `<choice maxOccurs="unbounded">` emits a single
  `(A | B)[]` instead of N parallel optional arrays — preserves document order
  natively and restores static exclusivity.

Excluded from both: mixed content, wildcards. Shape mismatches produce clear
validation errors, never silent asymmetry.

## 4. Naming — strip `@`, bare type names, per-field collision fallback

New defaults:

- Attribute keys lose the `@` prefix (`"@foo"` → `"foo"`).
- Top-level element anonymous types get the **bare element name**
  (`anonymous_Library_Type` → `Library`). Nested anonymous types keep the
  `Parent_Child_Type` scheme. Absorbs GH#161.
- **No naming flag at 1.0.** GH#182's ask becomes the default; variants belong to
  the post-1.0 config file. A temporary scaffolding flag for incremental landing
  on main is acceptable, deleted at the flip.

**Collision policy** (backed by a full-corpus census of 15,497 XSDs: `@`-strip
collides in 0.026% of files, bare naming in 2.3% — rare but real):

- Per-field fallback: the element wins the stripped name; the colliding attribute
  keeps its `@`. A colliding anonymous type keeps its `anonymous_` prefix.
- Every fallback emits a codegen warning **and** an explanatory comment in the
  generated file at the affected field/type.
- No hard error — users often cannot edit third-party schemas.
- Detection runs against the final emitted-name set (the dominant real-world
  collision is two anonymous types stripping to the same name across namespaces).
- The reserved-identifier set extends to generated module identifiers (`z`,
  `xmlRegistry`, helper imports).

## 5. Lexical retention — opt-in (GH#216)

Default off. `parseXml` no longer retains original lexicals per leaf;
`serializeXml` emits value-derived lexicals (shortest round-trip form, e.g.
`String(value)` — `1000`, not spec-canonical `1.0E3`). Byte-fidelity users
(diffs, hashes, XML content signatures) opt in via
`parseXml(xml, { retainLexicals: true })` — a runtime-only option, cheap to keep.

Rationale: retention never affects parse output (side channel only); for
float/double, canonical re-emission is spec-sound (the value space *is* IEEE 754);
and retention lets round-trip tests pass by echo without proving serializer
correctness. Tests switch to **value equality** plus pinned canonicalization
goldens (`001`→`1`, `1.0`→`1`).

Correctness sub-item: QName-valued content (`xsi:type`, QName-typed values) must
have prefixes remapped when serialize canonicalizes namespace prefixes.

## 6. xs:decimal — number default, exact opt-in (#233)

Default stays `z.number()` (float64), with the precision limit documented:
decimals beyond ~16 significant digits (common in financial XML) are lossy. An
opt-in exact mode (string-backed; facet/order machinery already operates on exact
lexicals since #136) serves precision-critical users. No zod-native or ecosystem
decimal exists; decimal.js is rejected (generated code stays dependency-free:
only `zod` + `xsd-to-zod`).

## 7. Deferred post-1.0

- **xor-types (GH#211):** purely additive, safe later.
- **Config file (#214):** no genuine consumer at 1.0 (the ergonomic flag
  is temporary; naming is a fixed default). Revisit triggers recorded on #214;
  when revived, use the scoped-down variant (JSON-only, explicit `--config`, no
  discovery).

## 8. License — MIT

Relicensed from GPL-3.0-only to MIT (#231). A codegen tool ships its runtime
inside consumers' applications, making GPL effectively "GPL projects only" and
leaving generated-code licensing ambiguous. README states explicitly: generated
code belongs to the user, no rights claimed.

## 9. Identity constraints — enforced at 1.0, default on (IRE-30, IRE-31)

`xs:key`, `xs:unique`, and `xs:keyref` are enforced by the zod tier from 1.0,
**on by default** — 1.0 is the deliberate breaking release, so the strictness
change is free here and costly later. Scoped uniqueness (`xs:key`/`xs:unique`)
attaches to the declaring element's schema; `xs:keyref` runs as a
document-level referential-integrity pass over the parsed tree, with constraint
metadata carried in xmlRegistry. Violations surface as structured `ZodError`
issues with paths, like every other parse failure. Documents whose
referential integrity is knowingly broken (partial exports, data being
repaired) can opt out of the pass alone via
`parseXml(schema, xml, { identityConstraints: false })` — schema validation
still runs. The generation-time warning
(#240) shrinks accordingly: it keeps covering only what remains unenforced
(mixed-content interleaving, plus identity constraints dropped as
unenforceable: xpaths outside the restricted subset, unresolvable keyref
targets).

## Documentation deliverables (fold into the 1.0 README rewrite)

- XML comments / PIs / DOCTYPE are dropped on parse
- CDATA normalizes to escaped text on round-trip (semantically identical)
- xs:decimal float64 precision limit + exact-mode flag
- xs:float values held as float64, strictly outside the float32 value space
  (benign for round-trip)
